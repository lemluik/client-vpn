## О проекте

КлиентВПН — open-source VPN-клиент, который управляет Xray-core как подпроцессом. Поддерживает VLESS+Reality, работает на Windows (системный прокси) и на Android (туннель VpnService), делает автоматический откат при сбое.

Клиент универсален: он работает с подпиской и ссылками любого провайдера, а не только с нашим сервисом. В нём можно держать несколько подключений одновременно — файл config.json, ссылку VLESS и подписку целиком, — а страна выхода выбирается прямо в интерфейсе по именам узлов, которые прислал провайдер.

**Архитектура:** Flutter UI (`home_screen` + `app_state`) → слой подключений (`share_link`, `subscription`, `provider`, `profile_store`, `region`) → сборка конфига для ядра (`temp_config`, `tun_config`) → общий слой `VpnCore` → ядро Xray-core как подпроцесс → VLESS+Reality → сервер → интернет. На десктопе ядро поднимает локальный прокси, и клиент переключает на него системные настройки через реестр Windows; на Android клиент передаёт ядру файловый дескриптор туннеля VpnService и работает без FFI и без Go-обёртки.

## Возможности

- ✅ Импорт конфигурации Xray-core (config.json)
- ✅ Ссылки профилей от любого провайдера: `vless://`, `trojan://`, `vmess://` (с именем из якоря или `ps`)
- ✅ Подписка: URL или тело в base64, несколько ссылок в столбик, обновление по кнопке
- ✅ Несколько подключений одновременно — каждое со своим названием, узлами и выбором
- ✅ Кэш последней успешной подписки: старт работает и без сети, а заголовки провайдера показывают остаток трафика
- ✅ Выбор страны выхода по именам узлов из подписки; выбор хранится и переживает перезапуск
- ✅ Смена страны на поднятом туннеле — с подтверждением и переподключением по новому маршруту
- ✅ Круглая кнопка подключения: цвет, кольцо и подпись следят за состоянием туннеля
- ✅ Журнал на отдельном экране: перед копированием адреса и ключи заменяются заглушками
- ✅ Чат поддержки на Matrix прямо в клиенте: узел и комнату даёт провайдер (заголовки подписки `chat-homeserver` и `chat-room`), либо узел вводится вручную; токен лежит в защищённом хранилище ОС (Keystore / Credential Manager), не в настройках приложения
- ✅ Комната — личная переписка «клиент + оператор»: клиент берёт её из `m.direct`, а не первую попавшуюся, поэтому чужих сообщений в ленте нет — разделение по составу участников, а не фильтром в интерфейсе
- ✅ Кнопки заявок рисуются из самой комнаты (её состояние `support.quick_replies`): набор текстов задаёт провайдер, в код клиента категории не зашиваются — приложение остаётся универсальным
- ✅ Очередь сообщений переживает перезапуск: неотправленное сообщение сохраняется со своим `txnId` и уходит под тем же идентификатором, поэтому узел не дублирует его
- ✅ Чат доступен и без добавленного подключения — это как раз тот случай, когда поддержка нужнее всего; история привязана к провайдеру и удаляется вместе с ним
- ✅ Windows: системный прокси (inbound `http` или `socks` на localhost)
- ✅ Android: туннель VpnService (TUN) — весь трафик уходит на сервер
- ✅ Ядро Xray-core 26.3.27 собрано внутри APK, скачивать его отдельно не нужно
- ✅ Валидация конфига перед подключением (`xray -test`)
- ✅ Проверка SHA-256 у `xray.exe` перед каждым запуском — подменённый бинарник не запускается
- ✅ Сохранение и восстановление ваших прежних настроек системного прокси
- ✅ Откат прокси при остановке Xray, закрытии окна и после сбоя
- ✅ Ожидание свободного локального порта перед запуском ядра — перезапуск сразу после отключения не роняет новое соединение

### Ограничения текущей версии

- ⚠️ iOS / macOS / Linux — в планах R3
- ⚠️ Windows: только system proxy (без TUN) — часть трафика может идти мимо
- ⚠️ Android: только arm64-v8a (официальный релиз Xray-core для Android не содержит других бинарников)
- ⚠️ Android: APK подписан отладочным ключом — обновление поверх релиза другим ключом потребует переустановки
- ⚠️ Страна выхода видна только если провайдер даёт имена узлам; ссылки без имён работают как одно подключение, как раньше
- ⚠️ Windows не рисует флаги из пар региональных индикаторов — там показывается полное название страны без значка
- ⚠️ Нет автоматического переключения на другой узел при сбое — выбор страны остаётся ручным
- ⚠️ Чат поддержки: только текст — без вложений, звонков и сквозного шифрования; учётку выпускает провайдер, самостоятельной регистрации на узлах нет
- ⚠️ Нет автообновления

## Установка

### Из релиза (рекомендуется)

**Windows**

1. Скачайте `ClientVPN-v0.2.1-Windows-x64.zip` из [Releases](https://github.com/lemluik/client-vpn/releases)
2. Распакуйте в любую папку
3. Запустите `client_vpn.exe`

> [!TIP]
> Если антивирус блокирует `xray.exe` — добавьте папку с приложением в исключения.

**Android**

1. Скачайте `ClientVPN-v0.2.0-Android-arm64-v8a.apk` из [Releases](https://github.com/lemluik/client-vpn/releases)
2. Установите файл (Android запросит разрешение на установку из неизвестных источников)
3. Откройте приложение и добавьте подключение — ядро уже внутри APK

> [!NOTE]
> При первом подключении система запросит разрешение на создание VPN-туннеля.

> [!IMPORTANT]
> APK в релизах пока собран до мультирегиона; сборки с выбором страны выхода и подписками выйдут следующим тегом.

## Использование

1. Нажмите **«+»** в верхней панели («Добавить подключение»)
2. Выберите источник: **«Ссылка или подписка»** — `vless://…`, `trojan://…`, `vmess://…`, URL подписки или несколько ссылок в столбик; либо файл **config.json**
3. Отметьте подключение в списке. Если провайдер назвал узлы странами, над кнопкой появится строка выбора — в ней список стран и число узлов в каждой
4. Нажмите круглую кнопку **«Подключить»**: во время подключения она крутит индикатор, после установки становится цветной с замком и подписью «Отключить»
5. Проверьте подключение: откройте https://ifconfig.co — должен показаться IP вашего сервера

Для отключения нажмите тот же диск. Смена страны на работающем туннеле спросит подтверждение и переподключит по новому маршруту. Журнал — кнопка в верхней панели; перед отправкой в поддержку его можно копировать как есть, адреса и ключи в нём уже заменены заглушками.

## Сборка из исходников

### Требования

- [Flutter SDK](https://docs.flutter.dev/get-started/install/windows) (stable, ≥3.6.0)
- [Visual Studio 2022](https://visualstudio.microsoft.com/) с workload **«Разработка классических приложений на C++»** — для сборки под Windows. Нужен ещё и компонент **ATL** (`Microsoft.VisualStudio.Component.VC.ATL`): без него сборка падает на `atlstr.h`
- Android SDK + NDK — только для сборки под Android (`flutter doctor` показывает принятые лицензии)
- [Git](https://git-scm.com/)

### Шаги

```powershell
# 1. Клонируйте репозиторий
git clone https://github.com/lemluik/client-vpn.git
cd client-vpn

# 2. Создайте Flutter-проект (или используйте существующий)
flutter create --org com.clientvpn --platforms=windows,android .

# 3. Скачайте Xray-core v26.3.27
# Вариант A: скрипт (Git Bash)
bash scripts/download_xray.sh

# Вариант B: вручную
# https://github.com/XTLS/Xray-core/releases/tag/v26.3.27
# Скачайте Xray-windows-64.zip, распакуйте xray.exe в assets/xray/
# Положите туда же geoip.dat и geosite.dat (иначе правило geoip:/geosite: не работает)

# 4. Добавьте в windows/runner/CMakeLists.txt перед закрывающим ):
#
#    add_custom_command(TARGET ${BINARY_NAME} POST_BUILD
#      COMMAND ${CMAKE_COMMAND} -E copy_directory
#      "${CMAKE_SOURCE_DIR}/../assets/xray"
#      "$<TARGET_FILE_DIR:${BINARY_NAME}>/xray"
#    )

# 5. Установите зависимости
flutter pub get

# 6. Соберите
flutter build windows
```

Готовый exe: `build\windows\x64\runner\Release\client_vpn.exe`

### Сборка Android

Нужен Android SDK (принятые лицензии, `compileSdk` и build-tools по версии Flutter). Ядро в git не лежит — его скачивает скрипт с проверкой SHA-256:

```powershell
# 1. Ядро Xray-core v26.3.27 под arm64-v8a в jniLibs
bash scripts/download_xray_android.sh

# 2. Зависимости и сборка
flutter pub get
flutter build apk --release
```

Готовый файл: `build\app\outputs\flutter-apk\app-release.apk` (только arm64-v8a, ядро уже внутри архива).

> [!WARNING]
> В `android/app/build.gradle.kts` релизная сборка подписана отладочным ключом. Перед публикацией в магазин или для обновлений поверх другой подписи настройте собственный ключ.

### Проверка окружения

```powershell
flutter doctor
```

Убедитесь, что «Visual Studio» показывает зелёную галочку. Если нет — установите Visual Studio 2022 Community с workload «Разработка классических приложений на C++».

## Архитектура

```
┌─────────────────────────────────────────┐
│         Flutter UI (Dart)               │
│  home_screen.dart · app_state.dart      │
│  диск подключения и список профилей     │
├─────────────────────────────────────────┤
│  share_link · subscription · provider   │
│  profile_store · region · log_mask      │
│  ссылки, подписки, профили, страна      │
├─────────────────────────────────────────┤
│           lib/vpn_core.dart             │
│      общий интерфейс ядра (abstract)    │
├──────────────────┬──────────────────────┤
│ desktop_core.dart│   android_core.dart   │
│ локальный прокси │  MethodChannel →      │
│ + реестр Windows │  TunnelService (Kotlin)│
├──────────────────┴──────────────────────┤
│  Process.start/kill  ·  VpnService TUN  │
├─────────────────────────────────────────┤
│  xray.exe / libxray.so (подпроцесс)     │
│  Xray-core 26.3.27 (MPL-2.0)            │
├─────────────────────────────────────────┤
│  VLESS+Reality → ваш сервер → интернет  │
└─────────────────────────────────────────┘
```

**Ключевые решения:**
- **Ядро как подпроцесс** — не FFI, не Go-обёртка. На десктопе `Process.start()`, на Android — тот же бинарник под именем `libxray.so`, потому что Android 10+ разрешает исполнять файлы только из каталога распакованных нативных библиотек.
- **Туннель на Android через унаследованный дескриптор** — libcore закрывает в дочернем процессе все дескрипторы, кроме стандартных, поэтому дескриптор туннеля передаётся как stdin, а ядро берёт его из переменной окружения `xray.tun.fd`.
- **System proxy через `reg`** — не win32 FFI. Команда `reg add` к HKCU\...\Internet Settings.
- **Валидация через `xray -test`** — штатная команда Xray, не своя логика.
- **Страна выхода — из имени узла** — провайдер сам называет узлы («Европа 1», «Кыргызстан 1»), клиент группирует их по этому названию и по нему же хранит выбор, поэтому узел можно перенумеровать или лишить флага — выбор сохранится. В конфиг ядра уходят только узлы выбранной страны, а если страна исчезнет из подписки, клиент откатывается на первую.
- **Конфиг ядра собирается в памяти** — ни одна ссылка не превращается в пользовательский config.json: файл нужен только ядру, поэтому он лежит в отдельной папке временных файлов на время работы и удаляется при выходе — там ключи пользователя.
- **Журнал по умолчанию замаскирован** — адреса узлов, идентификаторы и ключи заменяются заглушками и на экране, и при экспорте, так что в поддержку текст уезжает без секретов; переключателем можно показать оригинал.
- **Локальный порт дожидается освобождения** — ядро не стартует, пока предыдущий процесс не отдал inbound-порт, а принудительная остановка ждёт фактического завершения процесса. Это чинит перезапуск туннеля сразу после отключения.

## Известные проблемы

| Проблема | Решение |
|----------|---------|
| Антивирус блокирует xray.exe | Добавьте папку с приложением в исключения |
| System proxy не перехватывает весь трафик (Windows) | Ожидаемое ограничение: TUN на десктопе в планах. На Android трафик идёт через туннель VpnService |
| Прокси остался после crash | Клиент откатит его при следующем запуске, если прокси совпадает с установленным приложением. Вручную: `reg add "HKCU\...\Internet Settings" /v ProxyEnable /t REG_DWORD /d 0 /f` |
| xray.exe не найден | Скачайте его: `bash scripts/download_xray.sh`. Он попадёт в `assets/xray/`. После сборки проверьте `build\...\xray\xray.exe` |
| «Проверка целостности xray.exe не пройдена» | Бинарник повреждён или не соответствует закреплённой версии 26.3.27. Перекачайте: `bash scripts/download_xray.sh` |
| Подключение отклонено: «нет inbound http или socks» | Клиенту нужен локальный inbound в config.json, чтобы включить системный прокси. Добавьте inbound с протоколом `http` или `socks` |
| Android: «в конфиге нет прокси-исходящего соединения» | Для туннеля нужен outbound, который действительно уводит трафик на сервер (`vless`, `vmess`, `trojan`, `shadowsocks`, `socks`, `http`, `wireguard`). `freedom` и `blackhole` прокси не дают |
| Android: приложение не ставится на устройство | Сборка собрана только под arm64-v8a — на 32-битных устройствах установка невозможна |
| Android: ядро не запускается | `libxray.so` обязан быть в `android/app/src/main/jniLibs/arm64-v8a/` до сборки: `bash scripts/download_xray_android.sh` |
| «Порт 127.0.0.1:10808 занят другим приложением» | Локальный inbound ядра держит другое приложение (прокси, тор, второй VPN-клиент). Освободите порт и нажмите «Подключить снова» |
| Все узлы подписки в группе «Без имени» | Провайдер прислал ссылки без имён узлов — выбирать страну не из чего. Так работает и раньше: одно подключение со всеми узлами |
| На Windows вместо флага две латинские буквы | Windows не рисует флаги из пар региональных индикаторов, поэтому там показывается полное название страны без значка; на Android значок рисуется |

## Безопасность

- Не храните config.json в публичных местах и в папках облачной синхронизации — он содержит приватные ключи. Ссылки и подписки клиент сохраняет в приватной памяти приложения на обеих платформах; собранный для ядра конфиг живёт во временной папке только время работы и удаляется при выходе, а пользовательский config.json клиент не создаёт и не меняет
- Журнал по умолчанию замаскирован — адреса узлов, идентификаторы и ключи заменяются заглушками до показа и до экспорта; включать оригинал стоит только для себя
- Целостность `xray.exe` проверяется автоматически: скрипт скачивания сверяет SHA-256 архива и бинарника с зашитыми эталонами, а приложение повторно проверяет SHA-256 перед каждым запуском и отказывается стартовать с подменённым файлом
- Клиент сохраняет ваши прежние настройки системного прокси и возвращает их при отключении; аварийный откат трогает прокси только если он в точности совпадает с установленным этим приложением
- Телеметрии, проверки обновлений и аналитики в клиенте нет
- См. [SECURITY.md](SECURITY.md) для сообщения об уязвимостях
